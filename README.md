## ტერმინოლოგია

### Open List (ღია სია)
მდგომარეობათა კოლექცია, რომლებიც **აღმოჩენილია, მაგრამ ჯერ არ დამუშავებულა**.
- **BFS**-ში: FIFO `Queue` — მდგომარეობები მუშავდება მოსვლის თანმიმდევრობით
- **A\***-ში: `PriorityQueue` დალაგებული `f = g + h`-ით — ყველაზე პერსპექტიული მდგომარეობა ყოველთვის პირველი მუშავდება

### Closed List (დახურული სია)
მდგომარეობათა კოლექცია, რომლებიც **უკვე დამუშავდა** და აღარ უნდა განმეორდეს.
- **BFS**-ში: `HashSet` — ინახავს ნანახია თუ არა (დიახ/არა)
- **A\***-ში: `HashMap` — ინახავს **საუკეთესო f-სკორს** თითოეული მდგომარეობისთვის, რაც საშუალებას იძლევა ხელახლა შეფასდეს, თუ უკეთესი გზა მოიძებნა

---

## როგორ მუშაობს BFS

BFS (**Breadth-First Search** — სიგანეში ძიება) იკვლევს პაზლს **დონე დონე** — ჯერ ყველა 1-ნაბიჯიანი მდგომარეობა, შემდეგ ყველა 2-ნაბიჯიანი და ა.შ. არასდროს "გადახტება" წინ.

```
დონე 0:              [საწყისი]
                    /    |    \
დონე 1:           [A]  [B]  [C]       ← ყველა 1-ნაბიჯიანი
                 / \    |   / \
დონე 2:        [D][E] [F] [G][H]      ← ყველა 2-ნაბიჯიანი
                ...
დონე N:                          [მიზანი] ✅
```

**ნაბიჯ-ნაბიჯ:**
1. საწყისი მდგომარეობა → **Open List**-ში
2. **Open List**-იდან პირველის ამოღება
3. ყველა მეზობლის გენერაცია (ცარიელი უჯრა მოძრაობს ზემო/ქვემო/მარცხნივ/მარჯვნივ)
4. თითოეული მეზობლისთვის — თუ **Closed List**-ში არ არის:
   - დამატება **Closed List**-ში
   - თუ მიზანია → ამოხსნის დაბრუნება ✅
   - თუ არა → დამატება **Open List**-ში
5. გამეორება

**რატომ არის BFS ოპტიმალური?**
BFS ვერ მიაღწევს N+1 დონეს სანამ N დონე სრულად არ დამუშავდება.
შესაბამისად, **პირველი** მიზნის აღმოჩენა ყოველთვის **ყველაზე მოკლე გზით** ხდება.

## როგორ მუშაობს A*

A* არ იკვლევს ბრმად — ის ყოველთვის ირჩევს **ყველაზე პერსპექტიულ მდგომარეობას** ფორმულის დახმარებით:

```
f(n) = g(n) + h(n)
        ↑        ↑
   გავლილი    სავარაუდო
   ნაბიჯები   დარჩენილი
   (სიღრმე)   (მანჰეტენის მანძილი)
```

**მანჰეტენის მანძილი (ჰიურისტიკა h):**
თითოეული ფილისთვის გამოითვლება რამდენად შორს არის სამიზნე პოზიციიდან (ჰორიზონტალური + ვერტიკალური მანძილი). ყველა ფილის ჯამი = h(n).

```
მიმდინარე:      მიზანი:
7  2  3         1  2  3
4  5  6    →    4  5  6
1  8  _         7  8  _

ფილა 7: არის (0,0), უნდა იყოს (2,0) → მანძილი = 2
ფილა 1: არის (2,0), უნდა იყოს (0,0) → მანძილი = 2
h(n) სულ = 4
```

**ნაბიჯ-ნაბიჯ:**
1. საწყისი მდგომარეობა → **Open List**-ში (პრიორიტეტული რიგი)
2. **Open List**-იდან **ყველაზე დაბალი f**-ის ამოღება
3. თუ მიზანია → ამოხსნის დაბრუნება ✅
4. **Closed List**-ის შემოწმება — თუ უკეთესი გზა უკვე ცნობილია, გამოტოვება
5. ყველა მეზობლის გენერაცია
6. თითოეული მეზობლისთვის — თუ ახალი `f` უკეთესია **Closed List**-ში არსებულზე:
   - **Closed List**-ის განახლება ახალი საუკეთესო `f`-ით
   - მეზობლის დამატება **Open List**-ში
7. გამეორება

**რატომ არის A* ოპტიმალური?**
მანჰეტენის მანძილი არასდროს **გადაჭარბებს** რეალურ დარჩენილ ღირებულებას (admissible ჰიურისტიკა).
ეს გარანტიას იძლევა, რომ A* არასდროს გამოტოვებს ოპტიმალურ გზას — და ამავდროულად ცუდ გზებს უგულებელყოფს, რაც BFS-ზე გაცილებით სწრაფს ხდის.

## BFS vs A* — მთავარი განსხვავებები

| | BFS | A* |
|---|---|---|
| **სრული სახელი** | Breadth-First Search | A-Star Search |
| **Open List-ის ტიპი** | `Queue` (FIFO) | `PriorityQueue` (მინ. f) |
| **Closed List-ის ტიპი** | `HashSet` — ნანახია? | `HashMap` — საუკეთესო f სკორი |
| **იყენებს ჰიურისტიკას?** | ❌ არა | ✅ კი (მანჰეტენის მანძილი) |
| **ფორმულა** | მხოლოდ `g(n)` | `f(n) = g(n) + h(n)` |
| **მიზნის შემოწმება** | მეზობლის **აღმოჩენისას** | რიგიდან **ამოღების შემდეგ** |
| **პოულობს ოპტიმალურ გზას?** | ✅ კი | ✅ კი |
| **ეფექტურობა** | ყველაფერს იკვლევს | მიმართული — ბევრად ნაკლებს იკვლევს |
| **შეუძლია მდგომარეობის ხელახლა გახსნა?** | ❌ არა | ✅ კი (თუ უკეთესი გზა მოიძებნა) |
